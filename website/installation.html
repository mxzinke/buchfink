Installation

Buchfink aus dem Quellcode bauen

Fertige Installationspakete gibt es noch nicht — Buchfink ist in Entwicklung. Der Weg führt deshalb über den Quellcode: Werkzeuge einrichten, herunterladen, starten. Auf einem Rechner mit Go und Node.js dauert das ein paar Minuten.

Kurzfassungwenn Go, Node.js und Wails schon da sind
git clone https://github.com/mxzinke/buchfink.git
cd buchfink
npm --prefix frontend install
wails3 dev -config ./build/config.yml -port 9245

Alles Weitere unten in Ruhe erklärt.

Noch keine Version 1

Ein selbst gebauter Stand ist zum Ausprobieren gedacht. Wer damit echte Buchungen erfasst, sichert das Datenverzeichnis regelmäßig und prüft die Ergebnisse gegen die eigene Steuerberatung.

Voraussetzungen

Was auf dem Rechner sein muss

Buchfink läuft auf macOS, Windows und Linux. Gebaut wird jeweils für das System, auf dem man arbeitet; Cross-Compilation gibt es über einen Docker-Weg, den man für den Anfang nicht braucht.

Werkzeug Version Wofür
Go ≥ 1.22 Backend, Buchungslogik, Hash-Kette, Bankparser, XBRL
Node.js ≥ 20 Oberfläche bauen (React, TypeScript, Vite)
Wails v3 CLI aktuell Entwicklungsmodus, Desktop-Build und Paketierung
C-Toolchain Systemabhängig Nur für die WebView-Anbindung; die Datenbank selbst ist CGO-frei
Task optional v3 Kurzbefehle wie task dev, task build, task check
Typst optional aktuell Rechnungen lokal setzen und als PDF/A-3 prüfen
Python 3 optional ≥ 3.10 Prüfskripte für Design-Tokens und Bridge-Bindings

Werkzeuge einrichten

Je nach Betriebssystem

Go und Node.js lassen sich auch direkt von den Herstellerseiten installieren. Die folgenden Befehle sind der kürzeste Weg über die übliche Paketverwaltung.

macOS

TerminalHomebrew
brew install go node
brew install go-task typst        # optional
xcode-select --install            # Befehlszeilenwerkzeuge, falls noch nicht da

Linux (Debian, Ubuntu)

Terminalapt
sudo apt update
sudo apt install golang-go nodejs npm build-essential pkg-config \
                 libgtk-3-dev libwebkit2gtk-4.1-dev

Wails baut die Oberfläche unter Linux gegen GTK und WebKit — ohne diese Entwicklungspakete bricht der Build mit einer fehlenden Header-Datei ab. Liefert die Distribution ein zu altes Go oder Node.js, sind die offiziellen Archive von go.dev und nodejs.org der verlässlichere Weg.

Windows

PowerShellwinget
winget install GoLang.Go
winget install OpenJS.NodeJS.LTS
winget install Task.Task          # optional

Windows braucht zusätzlich die WebView2-Laufzeit. Auf Windows 11 und aktuellen Windows-10-Installationen ist sie bereits vorhanden.

Wails-CLI, auf allen Systemen gleich

Terminalgo install
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
wails3 doctor                     # meldet, was noch fehlt

go install legt die Binärdatei unter $(go env GOPATH)/bin ab. Falls wails3 danach nicht gefunden wird, gehört dieses Verzeichnis in den PATH.

Bauen und starten

Vier Schritte bis zur laufenden Anwendung

Repository klonen und Abhängigkeiten holen

Die Go-Abhängigkeiten zieht der erste Build von selbst; die Pakete der Oberfläche muss npm einmal installieren.

Terminalgit & npm
git clone https://github.com/mxzinke/buchfink.git
cd buchfink

go mod download
npm --prefix frontend install

Entwicklungsmodus starten

wails3 dev startet Go-Backend und Vite gemeinsam und öffnet das Anwendungsfenster. Änderungen an der Oberfläche sind sofort sichtbar, Änderungen am Go-Code lösen einen Neustart aus.

TerminalEntwicklungsmodus
wails3 dev -config ./build/config.yml -port 9245

# dasselbe kürzer, wenn Task installiert ist:
task dev

Beim ersten Start legt der Einrichtungsassistent den Mandanten an: Firmendaten, Geschäftsjahr, Datenverzeichnis. Danach steht der Wiederherstellungsschlüssel auf dem Bildschirm — er wird gebraucht, wenn die Datenbank auf einem anderen Rechner geöffnet werden soll, und lässt sich später nicht neu erzeugen.

Nur die Oberfläche im Browser ansehen

Für Arbeiten an der Gestaltung reicht der reine Vite-Server. Ohne Desktop-Laufzeit gibt es kein Backend: Jeder Aufruf meldet das offen, statt Beispieldaten vorzutäuschen. Zum Buchen ist dieser Modus also nicht gedacht.

TerminalVite allein
npm --prefix frontend run dev     # http://127.0.0.1:9245

Desktop-Build und Paket erzeugen

build erzeugt die ausführbare Datei, package daraus das systemübliche Paket — .app unter macOS, ein Installer unter Windows, .deb beziehungsweise AppImage unter Linux. Das Ergebnis liegt unter bin/.

TerminalBuild
wails3 build                      # oder: task build
wails3 package                    # oder: task package

./bin/buchfink                    # oder: task run

Beitragen

Was vor einem Pull Request läuft

Buchfink ist Buchhaltungssoftware — ein Fehler hat Folgen für Jahresabschluss und Betriebsprüfung. Deshalb prüft das Projekt mehr als nur Kompilierbarkeit. Der gesammelte Durchlauf steht als eine Aufgabe bereit.

TerminalPrüfungen
task check                        # Formatierung, vet, Tests, Design, Bridge

# einzeln, ohne Task:
gofmt -l internal main.go
go vet ./internal/...
go test ./internal/...
python3 scripts/check_design_tokens.py
python3 scripts/check_bridge_bindings.py

# Oberfläche:
npm --prefix frontend exec tsc -- --noEmit
npm --prefix frontend run build

Design-Tokens

check_design_tokens.py lässt in frontend/src/ weder Hex-Farben noch Klassen der Tailwind-Standardpaletten durch. Die verbindlichen Werte stehen im Design-Konzept.

Bridge-Bindings

check_bridge_bindings.py vergleicht frontend/src/services/bridge.ts mit den gebundenen Go-Methoden. Ein Tippfehler im Methodennamen fällt so beim Prüflauf auf und nicht erst im laufenden Fenster.

Neue Abhängigkeiten

Nach jeder Änderung an den Abhängigkeiten gehört python3 scripts/gen_third_party_notices.py (oder task notices) dazu. Copyleft-Lizenzen bitte vorher im Issue ansprechen — sie können über die Kompatibilitätsklausel der EUPL die Lizenz des Gesamtwerks verschieben.

Alles Weitere — Commit-Stil, Tests für Buchungslogik, die Vereinbarung über Beiträge — steht in CONTRIBUTING.md.

Stolpersteine

Was erfahrungsgemäß hakt

Meldung Ursache und Abhilfe
wails3: command not found $(go env GOPATH)/bin liegt nicht im PATH. Verzeichnis ergänzen oder die Binärdatei mit vollem Pfad aufrufen.
webkit2gtk-4.1 not found Unter Linux fehlen die Entwicklungspakete für GTK und WebKit. Siehe den apt-Befehl oben; auf Fedora heißen sie gtk3-devel und webkit2gtk4.1-devel.
go test ./... schlägt fehl main.go bindet frontend/dist ein, das es vor dem ersten Frontend-Build nicht gibt, und internal/wailsbridge zieht Wails samt GTK-Headern. task test listet deshalb genau die Pakete auf, die Tests haben.
unknown bound method name Der Methodenname in bridge.ts passt nicht zum voll qualifizierten Go-Namen. python3 scripts/check_bridge_bindings.py zeigt die Abweichung.
„Keine Verbindung zum Buchfink-Backend“ Die Oberfläche läuft im Browser statt in der Desktop-App. Das ist kein Fehler, sondern die ehrliche Meldung aus npm run dev. Zum Buchen wails3 dev starten.
Mandant lässt sich nicht öffnen Das Geheimnis liegt im Schlüsselbund des Rechners, auf dem eingerichtet wurde. Auf einem anderen Rechner braucht es den Wiederherstellungsschlüssel aus der Einrichtung.
